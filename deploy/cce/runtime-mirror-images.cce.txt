# =============================================================================
# SkillHub on CCE —— 第三方运行时镜像映射表
#
# 用法（由 deploy/cce/mirror-images.sh 读取，不直接执行）：
#   SWR_REGION=cn-north-4 SWR_ORGANIZATION=skillhub ./deploy/cce/mirror-images.sh --dry-run
#   SWR_REGION=cn-north-4 SWR_ORGANIZATION=skillhub ./deploy/cce/mirror-images.sh
#
# 格式与 scripts/mirror-runtime-images.sh、deploy/runtime-mirror-images.txt 一致：
#   每行「源镜像 目标镜像」两列，空格分隔；# 开头为注释；空行忽略。
#   目标列会展开为 ${MIRROR_REGISTRY}/${MIRROR_NAMESPACE}/<目标镜像>，例如
#     bitnami/postgresql:db2312d9b243
#     → swr.cn-north-4.myhuaweicloud.com/<ORG>/bitnami/postgresql:db2312d9b243
#   （目标列保留 bitnami/、library/ 之类路径，只替换 registry/org，
#     这样 Helm values 里只需覆盖 image.registry 就能指向 SWR。）
#
# 为什么 digest 不能省（Bitnami 相关行必填）：
#   * 这些 digest 来自 charts/skillhub/values.yaml（postgresql 18.6.10 / redis 25.5.3
#     的 chart 默认镜像），是「安装与回滚可复现」的唯一锚点；
#     bitnami 的 tag 会随上游重建而漂移，只有 digest 能保证同步到与 chart 校验过的同一份字节。
#   * digest 可用 `docker buildx imagetools inspect <源镜像>` 或 `regctl manifest head <源镜像>` 复核。
#   * busybox 在 chart 中按 tag 引用（server.dependencyWait.image.tag=1.37），
#     这里仍写成 tag@digest：目标 tag 保持 1.37 供 chart 引用，内容由 digest 锁定。
#
# 镜像同步是发布操作（会写入 SWR），不是只读检查：
#   * 验收要比对「源 → 目标」的 manifest digest，并逐平台核对，不能只看命令退出码；
#     参考命令：regctl manifest head <目标镜像>；docker buildx imagetools inspect <目标镜像>
#   * 多平台 index 会被 scripts/mirror-runtime-images.sh 重建（它刻意丢弃 attestation
#     子清单，避免部分仓库拒绝 application/vnd.oci.empty.v1+json 配置），因此目标 digest
#     可能与源 digest 不同——busybox 携带 attestation 子清单，digest 必然变化。
#     需要按 digest 固定引用时（如 values-cce-incluster-db.yaml 的 image.digest），
#     请以同步后实测到的目标 digest 为准；不确定就改用本文件里的目标 tag。
#   * 跨架构可用性（2026-11 实测上游 index）：
#       busybox:1.37                      linux/amd64, arm/v5-v7, arm64/v8, 386, ppc64le, riscv64, s390x
#       bitnami/postgresql|redis|*exporter linux/amd64, linux/arm64
#     同步脚本会复制 index 下全部可运行平台，CCE 的 amd64 节点与 arm64 节点都能用；
#     只用单平台的场景也无需裁剪（多平台只是占用更多 SWR 空间）。
#
# 不在本表的内容：
#   * skillmall-server / web / scanner（github-sync 仍为 skillhub-github-sync）：由 deploy/cce/build-images.sh 自行构建推送。
#   * nginx、prometheus、grafana、minio/silo、rustfs：docker-compose 交付用的镜像，
#     CCE 场景不需要（web 镜像自带 nginx，监控走 AOM/托管服务）；
#     如果要在 CCE 上跑 compose 形态，复用 deploy/runtime-mirror-images.txt。
# =============================================================================
