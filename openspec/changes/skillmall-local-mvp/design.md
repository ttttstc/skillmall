# SkillMall 本地首期设计基线

状态：需求与设计讨论基线；未实现、未运行、未验收。验收合同见 [规格](specs/skillmall-local-mvp/spec.md)，用户目标与范围见 [提案](proposal.md)。

## 1. 产品边界与角色

SkillMall 首期是独立运行的公开 Skill 市场，以本地测试环境为交付和验收范围。保留 UCD 的市场体验与视觉语言，顶部仅展示市场自身可用的品牌、导航与登录入口；未来才集成 AI 基础设施看板。SkillHub 注册中心是现有技术底座，CLI 是消费入口，CANNWork 的 Skill 开发工具不由本期建设。

角色分为匿名访客、本地登录用户和一个以部署配置指定的调试管理员。GitCode 不作为首期身份源，本地账号也是临时方案，不设计 GitCode 绑定、自动合并或迁移。游客读公开数据和下载；登录用户管理自身资源、发布与收藏；管理员具备官方标识维护和下架权限。权限必须由服务端校验，管理员身份不可由普通注册或客户端声明取得。

领域术语沿用现有词汇表：**技能所有者**与所在空间负责人不同；**历史作者**不随当前所有者变化。市场增加的讨论术语：**发布者**是本次发布的市场用户，**来源**是原始代码仓及其快照，**官方标识**是管理员作出的市场运营标识，不等同于原作者、扫描结果或安全认证。准确来源作者信息无法获取时不编造。

## 2. 页面与 UCD 对齐

覆盖首页、全部技能、详情（README／安装说明／文件／版本历史）、本地上传及代码仓导入、我的 Skill 和我的收藏；登录／注册及必要的管理入口复用并适配现有能力。首页保留推荐、近期热门、下载热榜、最新上线、领域 Skill，预置一级分类：设计、开发、测试、工程、项目管理、其他。没有正式分类资料时不臆造下级。专题区域及相关入口不在首期。

对比用户提供的 UCD：已有页面的布局、风格、交互及状态以原图为基准；独立顶部导航、移除专题、“提交审核”改为直接发布、显示未评测而非安全通过，是用户确认的差异。没有覆盖的加载、空结果、失败、无权限、冲突状态按同一视觉语言补足。无需依赖已有看板运行。

推荐是通用展示而非个性化，换一换返回另一组实际公开 Skill；不足时允许重复或展示不足，不伪造数据。具体通用排序与换组细节在实施时选可复用的最小方式，不改变其非个性化语义。

## 3. 主要流程

### 发布和版本

用户登录 → 选择本地包或 GitCode 公开仓 → 检查并预览文件 → 填写基础信息、领域及版本 → 发布 → 成功后公开发现和分发。包边界保留路径、大小、格式和必要字段等输入校验；这些检查不构成领域规范评测或安全扫描。UCD 本地上传页标注 10 MB 和包含 SKILL.md；需核对现有包限制、文件夹／ZIP 行为及后端一致性，不因仅改前端而宣称已支持。

新内容作为独立版本保存，旧版本保留且按真实状态提供历史查看与下载；发布失败不得把未准备好的新版本作为公开 latest。作者移除与管理员下架分别授权和记录，公开发现、详情、文件、resolve 和下载应一致阻断；不承诺撤销已经下载的文件或已经签出的短期存储链接。下架恢复暂不设计，不隐含允许作者重新发布或要求审核。

现有文档描述普通 PUBLIC 上传要求扫描并进入审核，而管理员直发仍可能触发扫描与就绪约束。目标是当前首期普通用户直发，不是复用特权身份或仅隐藏审核界面；实现前必须核对 Web、CLI、兼容入口、所有权、审计、搜索索引和下载条件，并保护旧数据与无关使用场景。是否需要受控产品配置及其迁移属于实施设计，不在本基线凭空确定。

### GitCode 公开仓手动导入

输入公开仓地址 → 解析默认分支当前 commit → 固定仓库与完整 commit → 发现 Skill 路径 → 用户选择 → 从同一快照预览 → 发布时使用相同内容与来源元数据。每个版本保留仓库地址、仓库内路径、完整 commit 和内容摘要；UI 可展示短 commit 和来源链接。导入更新须由用户主动触发并产生新版本；不自动追踪或同步。

仅允许约定的 GitCode 公开来源；仓库不可达、路径缺失、不是 Skill 或取回内容与固定快照不一致时清晰失败，不创建可公开的错误版本。地址、重定向、网络访问、归档解压及临时文件边界需复用或补齐现有保护，避免把任意地址当成服务器可访问资源。认证仓、其他来源和凭据收集均不在本期。

现有 GitHub 同步对固定 commit 采集，并通过版本到摄入记录的关联保存 commit；它包含定时任务与独立审核流程，不证明 GitCode 手动导入已存在。设计只借鉴可复用的来源追溯和包接收机制，不要求复制完整同步系统。

### 搜索、统计与安装

匿名市场只展示当前公开、可分发的 Skill，已移除或下架的数据不得靠搜索索引延迟继续暴露；搜索与存储维持现有可替换接口。近期热门按最近 7 天下载次数，累计热榜按累计下载次数，最新上线按 Skill 首次公开时间，而非每次版本更新；必须检验现有 newest 字段的实际语义。收藏与下载分别呈现，不引入点赞。

现有实现有 Skill 级和版本级累计下载计数与下载事件；目前未证明可直接查询近 7 天数据。若无时间维度，只增加计算热榜所需的最小持久统计。统计口径沿用现有下载事件语义并公开一致说明；请求计数不等于实际安装成功人数。无历史数据时不虚构回填；具体窗口边界、延迟和去重以实施验证后的明确口径为准。

默认安装目标及命令以实际验证的 SkillHub CLI 为准，不声称提供 CANNWork 原生命令。市场提供完整坐标和本市场来源，保留手动下载。安装不执行包内脚本，同一目标已有不同来源同名内容时应阻断并提示，不能自动覆盖；不得对未经验证的手动复制指令承诺具备冲突保护。

## 4. 现状、差异与待验证

| 范围 | 当前证据 | 首期缺口或待验证 |
|---|---|---|
| 注册／认证 | 现有本地注册登录及自助注册开关 | 本地注册、指定管理员、越权保护及真实会话 |
| Skill 身份 | namespace + slug 唯一，存在个人 namespace 建立逻辑 | 不同用户同名公开发布及安装链路 |
| 发布生命周期 | 现有业务文档要求普通公开发布扫描与审核 | 直接公开的新规则、全入口一致性及审计；不把目标写成现状 |
| 代码仓 | GitHub 同步固定 commit 且版本关联摄入记录 | GitCode 手动导入、多个 Skill、快照与版本持久追溯 |
| 搜索和榜单 | 存在搜索 SPI、累计下载及现有排序 | 7 天统计和首次公开时间、下架过滤、多维 UCD 交互 |
| CLI | 可指定 registry，存在目标和来源冲突保护 | 本地真实下载、同名冲突、目标平台与指引 |
| 自动质检 | 项目有扫描器封装及审核链路 | 本期不实施自动质检，前端不可伪造通过 |

现有规则中可公开发布及关闭扫描的具体条件以实际实现和测试再次核对。若用户确认的目标与旧业务合同冲突，实施需作为显式产品变更记录，并核对依赖入口，不静默改写旧文档。

## 5. 测试边界和本地验收

首选一个外部用户路径贯穿浏览器、应用 API、数据库及本地依赖：注册／登录 → 发布 → 匿名搜索和详情 → 下载 → 更新／移除。该边界验证页面和真实服务协同；沿用现有发布、搜索、匿名详情 E2E 测试。GitCode 的稳定自动化验证在服务边界使用受控仓库响应及固定 commit，覆盖分支移动、仓库不可用和多个 Skill；另做一次真实公网 GitCode 仓库本地联调。CLI 复用既有安装测试边界，在真实临时目录验证冲突与保留原文件。API 权限、状态投影和计数可按现有服务／集成测试补充，避免引入多层仅用于测试的新接口。

验收以 [规格](specs/skillmall-local-mvp/spec.md) 为准；真实运行前检查启动脚本的副作用和依赖，不停止或清理现有数据。记录命令、环境、通过／失败／未运行结果。GitCode 联调受网络或源站限流阻塞时如实报告，不视作通过。构建、截图和静态检查不等于完整运行或公网部署。
