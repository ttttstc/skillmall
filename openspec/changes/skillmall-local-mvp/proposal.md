## Problem Statement

用户需要一个符合既有 UCD 的 Skill 市场，在一个入口发现、获取、发布和管理 Skill。现有 SkillHub 提供注册中心和部分治理能力，但其页面、公开发布规则及代码仓来源与 SkillMall 的首期目标不完全一致。首期先在本机完成真实可用的闭环，验证现有能力与必要改造，再考虑后续集成。

## Solution

以现有 SkillHub 为基础，建设独立运行的 SkillMall。访客可发现、查看和下载公开 Skill；本地账号用户可发布、更新、移除和收藏 Skill；指定管理员管理官方标识及下架。用户通过本地包或 GitCode 公开仓发布，仓库导入绑定实际 commit。页面对照 UCD，已确认的范围变化明确列出。自动质检等后续能力不以假数据代替。

## User Stories

1. 作为访客，我希望无需登录浏览首页，以便了解市场内容。
2. 作为访客，我希望按名称或描述搜索 Skill，以便找到解决问题的工具。
3. 作为访客，我希望查看全部 Skill 和对应的列表／卡片视图，以便按习惯浏览。
4. 作为访客，我希望查看预置领域分类，以便缩小查找范围。
5. 作为访客，我希望查看通用推荐并换一组，以便发现不同的 Skill。
6. 作为访客，我希望查看近期热门，以便了解最近受关注的 Skill。
7. 作为访客，我希望查看累计下载热榜，以便了解下载情况。
8. 作为访客，我希望查看最新上线，以便发现新发布的 Skill。
9. 作为访客，我希望看到名称、作者、简介、领域、收藏和下载数据，以便比较 Skill。
10. 作为访客，我希望查看详情和使用说明，以便判断是否适合我的场景。
11. 作为访客，我希望查看 Skill 文件和目录，以便了解分发内容。
12. 作为访客，我希望查看版本历史和变更说明，以便了解不同版本。
13. 作为访客，我希望下载公开 Skill 的 ZIP 包，以便手动安装。
14. 作为访客，我希望获取经过验证的安装说明，以便选择可用的安装方式。
15. 作为访客，我希望知道 Skill 未评测，以免误以为它已通过安全检查。
16. 作为新用户，我希望注册和登录本地账号，以便参与发布。
17. 作为用户，我希望退出登录，以便结束当前会话。
18. 作为用户，我希望上传本地 Skill 包并预览文件，以便确认提交内容。
19. 作为用户，我希望从 GitCode 公开仓导入，以便复用仓库中的 Skill。
20. 作为用户，我希望在多 Skill 仓库中选择目标，以便只发布所需内容。
21. 作为用户，我希望看到导入 commit，以便知道内容来自哪个仓库快照。
22. 作为用户，我希望填写 UCD 中要求的基本信息，以便其他人理解 Skill。
23. 作为用户，我希望选择预置领域，以便 Skill 被正确发现。
24. 作为用户，我希望在提交时获得必要格式和文件问题提示，以便修正后发布。
25. 作为用户，我希望提交成功后 Skill 直接公开，以便他人发现和下载。
26. 作为用户，我希望查看自己发布的 Skill，以便管理内容。
27. 作为用户，我希望修改自己有权维护的 Skill 信息，以便保持信息准确。
28. 作为用户，我希望发布 Skill 新版本和变更说明，以便交付更新并保留版本历史。
29. 作为用户，我希望主动从 GitCode 导入新的仓库快照，以便控制更新时机。
30. 作为用户，我希望移除自己的 Skill，以便停止公开分发。
31. 作为用户，我希望收藏和取消收藏，以便稍后查找。
32. 作为用户，我希望查看我的收藏，以便管理感兴趣的 Skill。
33. 作为用户，我希望不能编辑他人的 Skill，以便内容归属得到保护。
34. 作为发布者，我希望与其他发布者使用同名 Skill，以便不因全局名称占用而无法发布。
35. 作为安装者，我希望同名目录冲突时停止并提示，以便已有内容不会被自动覆盖。
36. 作为管理员，我希望导入并维护官方 Skill，以便提供官方内容。
37. 作为管理员，我希望明确设置官方标识，以便区分官方内容和普通社区内容。
38. 作为管理员，我希望下架不适合公开的 Skill，以便停止后续发现和下载。
39. 作为管理员，我希望操作留有记录，以便追踪管理行为。
40. 作为本地验收者，我希望用真实 GitCode 公开仓验证导入，以便确认来源和 commit 对应。
41. 作为用户，我希望请求失败、列表为空或无权操作时得到真实提示，以便理解当前状态。
42. 作为维护者，我希望复用现有注册中心和接口，以便避免大规模重构与破坏兼容性。

## Implementation Decisions

- 注册中心仍是产品核心，优先复用 SkillHub 的账号、命名空间、技能包、版本、发布、搜索、存储、收藏、管理及 CLI；实现前以代码和测试核实可复用边界。
- 本地账号仅为临时认证方式。未来 GitCode 登录、账号绑定及数据迁移均不属于本期设计，不自动合并用户。
- Skill 的发布者／当前所有者、原作者及仓库来源是不同概念；官方标识由管理员明确设置。
- 用户上传的 Skill 首期均为公开，普通用户提交成功后可被公开发现及下载；这是一项目标规则，与现有普通公开发布的审核和扫描链路存在已知差异，必须检查所有受影响入口、事件、就绪条件和审计。
- 同名 Skill 以发布者相关的空间与 slug 等完整坐标区分；具体映射须检查现有 namespace 合同及安装兼容性，不改写已有公开协议。
- 本地包和 GitCode 导入经过同一发布边界。导入固定默认分支解析出的 commit，预览和发布绑定同一个快照；每个发布版本可追溯来源仓库、Skill 路径及 commit。仅支持公开 GitCode 仓库，更新由用户主动发起。
- 版本内容更新新建版本并保留历史；作者移除和管理员下架是不同操作。下架后公开搜索、详情、解析和下载不再提供内容；已下载文件无法收回。下架恢复流程不在本期。
- 分类预置设计、开发、测试、工程、项目管理、其他六个一级类目；不虚构多级目录。首页通用推荐不声称个性化。近期热门为最近 7 天下载量，下载热榜为累计下载量，最新上线按首次公开时间倒序。
- 数据没有实际评测结果时显示未评测；不能显示安全通过或虚构分数。基础格式与包安全处理属于系统接收要求，不代表自动质检或安全认证。
- 视觉及已有交互按 UCD 复刻；独立导航、无专题区域、直接发布文案和未评测状态为本期已确认差异，缺失状态按同一设计语言补齐。
- CLI 和手动安装均须验证实际操作；无法验证的命令不展示为可用。不同来源同名安装发生冲突时不得自动覆盖。
- 遵守现有模块依赖、可替换的搜索与存储接口、用户身份类型和审计约束；不得为适配市场破坏既有 SKILL.md、命名空间或 CLI 合同。

## Testing Decisions

- 优先从用户可见的浏览器及公开 API 边界验证完整行为，不测试内部实现细节；沿用现有端到端发布、搜索、匿名详情及 CLI 安装测试体系。
- 覆盖注册登录、权限与越权、上传与公开、版本历史、作者移除、管理员下架、来源与 commit 绑定、同名 Skill、收藏、领域筛选、榜单及空态和错误态。
- GitCode 边界使用固定 commit 的可控测试替身覆盖失败与竞态；最终本地验收另使用真实 GitCode 公开仓，不能以替身或静态检查冒充真实联调。
- CLI 使用真实本地临时目录验证指定注册中心、完整包、同名冲突和未覆盖；确认手动安装指引实际可执行。
- 对 UCD 已涵盖页面和交互逐项比对，并记录约定差异；本地服务启动和端到端结果应与单元测试、构建和静态检查分开报告。

## Out of Scope

专题及 Skill Suite 作为专题复用；独立点赞；领域规范包和自动规范校验；自动安全扫描、质检工作流及综合评测；举报；下架后的恢复操作；优秀贡献者／使用者榜单；CANNWork 的开发脚手架、实时校验和打包；看板导航与身份集成；GitCode 登录与本地账号绑定；代码仓自动同步、私有仓、GitHub 仓导入；生产或公网部署。
